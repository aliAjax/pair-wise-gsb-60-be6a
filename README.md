# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖与报告追踪
- `/audit`：跨信号审计时间线和 JSON 报告导出

```bash

npm run build
```

无后端服务，页面使用确定性模拟数据，并将信号、证据、版本和审计记录持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。

## 可恢复版本流程

- **证据登记**：补入证据时登记来源批次与内容指纹（题录 + 核查说明 + 强度的归一化散列）。同一指纹只追加来源批次关联，不重复建档；同来源内容变化记为修订（revision 递增）。
- **结论版本**：每个结论版本记录其引用的证据版本快照（证据号 + 指纹 + 修订号）。被引用证据变化后，旧结论失效转待复核并保留，复核人（须与作者不同）确认或形成新版本前，不能继续处置该信号。
- **并发保护**：所有变更携带信号修订号，经 Web Lock 互斥的读-校验-写提交；两个标签页同时提交同一信号时，后到者判冲突、载入最新内容重新校验，不覆盖先行结果。跨标签页通过 `storage` 事件同步。
- **可恢复迁移**：v1 台账幂等迁移到 v2（按信号号与迁移清单去重）。迁移写入失败时旧数据原样保留、继续可读，顶部横幅可重试，只补未迁移信号，不重复导入。
- **同一版本**：总览、信号详情、批次追踪和审计共用同一台账存储，页头显示台账架构版本与全局修订号（v2 · R{n}）。
